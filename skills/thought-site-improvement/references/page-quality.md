# ページの品質基準

公開しているページが「読む理由のある主張」になっているかを、文体ではなく構造で判定する。

## 三つの要素

思想として再利用できる文章には、次の三つが揃っている。

- **結論**：何を選ぶか、何をそうみなすか。
- **適用条件**：どの状況で成り立ち、どこから成り立たないか。
- **理由**：なぜそう判断するか。

条件のない結論は標語であり、別の場面へ持ち出せない。

理由のない結論は、変えるべきときに変えられない。

## 判定

`npm run audit` は本文を文単位に分け、次を数える。

- 主張：断定で終わる12文字以上の文。
- 問い：「〜か」で終わる文。
- 条件：`とき` `なら` `場合` などの語の種類。
- 理由：`ため` `なぜ` `理由` `ではなく` などの語の種類。

そのうえで4段階に判定する。

| 判定 | 意味 | 対応 |
| --- | --- | --- |
| 空 | 主張が1文以下。ページの説明文しかない。 | `draft` のまま。埋めずに問いとして残す。 |
| 骨組み | 結論はあるが、条件か理由が足りない。 | `draft`。根拠が揃った回に条件と理由を足す。 |
| 育成中 | 結論と、条件または理由が揃った。 | `evolving` にできる。 |
| 公開に足る | 結論・適用条件・理由が揃った。 | `published` にできる。 |

## カテゴリごとの基準の違い

`principles` `beliefs` `frameworks` は、別の場面へ持ち出すための文書なので、適用条件を必ず求める（主張6文以上）。

`essays` は一つの問いを背景と反論まで含めて扱うため、より長い分量を求める（主張10文以上）。

`decisions` `influences` は一つの出来事を記録する文書なので、選択と理由が揃えばよい（主張3文以上）。

`changelog` と `knowledge/daily` は記録であり、この基準では測らない。

## 失敗として扱う条件

**公開状態が実質を上回っている場合だけ**、監査は失敗する。

`published` と書きながら中身が骨組みなら、読者に対して過大な表示になっている。

逆に、実質が `status` を上回っているのは失敗ではない。

昇格するかどうかは本人の判断であり、機械が公開を決めない。

## 数値を目的にしない

この判定は、書けているかどうかを外から見るための道具である。

判定を通すために `ため` や `場合` を挿入しても、文章は良くならず、指標だけが壊れる。

判定と読後感が食い違うと感じたら、文章ではなく基準側を直す。

## ページを減らす判断

次の場合は、育てずに減らす。

- 別のページと同じ主張をしている：中心となる一枚へ統合し、もう一方を削除する。
- 一年以上、根拠が一件も増えていない：問いとして関心が続いていないため、削除を検討する。
- 主張を支えていた前提が変わった：`changelog/` に撤回の理由を書いてから削除する。

削除は `changelog/` への記録とセットで行う。

記録のない削除は、思想を変えたのか、面倒で消したのか、後から区別できない。
