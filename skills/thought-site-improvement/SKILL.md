# 公開している思想を育てる

このサイトの問題は、ページ数が足りないことではなく、主張のないページが公開されていることである。

ループの目的は記事を増やすことではなく、**公開されている一枚一枚が、読む理由のある主張になっている状態を保つこと**にある。

## 何よりも先に守ること

本人が実際に考えていないことを書かない。

根拠がないページは、埋めずに `status: draft` のまま残す。

もっともらしい一般論で空白を埋めると、そのページは二度と「本人の思想」として扱えなくなる。

一回の実行で「育てるページが1本もなかった」は、正常な結果である。

## 一回の実行で扱う範囲

育てるページは**最大2本**まで。

薄い文章を全ページへ一度に足すと、全ページが等しく薄いまま量だけ増える。

`essays/` は自動で書き起こさない。

本人がまとまった論考を求めた場合だけ作る。

## 手順

### 1. 現状を測る

```bash
npm run audit
```

各ページの主張・問い・条件・理由の数と、`空` / `骨組み` / `育成中` / `公開に足る` の判定、日次ノート由来の根拠件数が出る。

判定基準を確認するときは [ページの品質基準](references/page-quality.md) を読む。

`公開状態が実質を上回っている` と報告されたページがあれば、**それを最優先で直す**。

### 2. 育てる対象を決める

「今回育てる候補」から、根拠件数の多いページを選ぶ。

根拠が0件のページは選ばない。

同じ主張が別カテゴリのページと重なる場合は、新しく書かずに統合する。

### 3. 根拠を確かめる

`knowledge/daily/` を読み、そのページのテーマに触れた記述を集める。

日次ノートが足りない場合は、`daily-conversation-knowledge` スキルで対象日の抽出を先に行う。

一日分の発言しか根拠がない主張は、カテゴリ別の文書へ上げない。

異なる日付か異なる場面で繰り返し確認できた内容だけを対象にする。

### 4. 書く

根拠から主張へ変える手順は [根拠から書く](references/writing-from-evidence.md) に従う。

一つの主張につき、結論・適用条件・理由を書く。

条件のない断定と、理由のない結論は残さない。

### 5. 公開状態を合わせる

- 主張がない、または問いだけ：`status: draft`（サイトでは「育てている問い」として題だけ載る）
- 結論と、条件または理由が揃った：`status: evolving`
- 結論・適用条件・理由が揃った：`status: published`

`updated` を実行日にする。

実質が伴わないページの `status` を上げない。

逆に、根拠が古びて支持できなくなった主張は `status` を下げるか、`changelog/` に撤回として残す。

### 6. 検証する

```bash
npm run audit && npm run build
```

`npm run audit` が失敗した状態でコミットしない。

### 7. 記録して出す

変更したページ、変更内容、根拠にした日次ノートの日付、理由を `changelog/YYYY.md` へ短く追記する。

`claude/blog-improvement-YYYY-MM-DD` ブランチへコミットしてpushし、PRを作る。

PR本文には、監査結果の要約（何ページが空か、今回どれを育てたか、なぜ他を育てなかったか）を書く。

PRを作る手段がない実行環境では、pushまで行い、同じ要約と比較用URLを報告する。

`main` へ直接pushしない。

## やらないこと

- 根拠のない主張を書く。
- ページ数や文字数を目標にする。
- 判定を通すためだけに「ため」「場合」などの語を足す。
- 本人が明示していない価値観を、発言から推測して原則として確定する。
- 同じ内容を複数カテゴリへ複製する。
