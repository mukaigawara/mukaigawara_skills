# 確認

確認のない怠惰なコードは未完成である。

## 残す確認

自明でないロジックには、実行可能な確認を一つ残す。

一つとは、壊れたら落ちる最小のものである。

- assert を含む短いデモ、または自己検査。
- 小さなテストファイル一つ。

フレームワーク、fixture、テスト用の階層は足さない。既存のテストの置き方がある場合は、それに合わせる。新しい置き方は作らない。

自明な一行、既存関数への委譲だけ、設定値の変更には、確認は不要である。

自明でないものの目安は、分岐、状態、パース、同時実行、守るべき不変条件があることである。

## `ponytail:` コメント

意図して角を切り、既知の上限がある簡略化には、`ponytail:` コメントを付ける。

コメントには、いま受け入れている上限と、それを超えたときの改善経路を書く。

```text
# ponytail: プロセス全体のロック。キーごとの排他が必要になったら per-key mutex に替える
# ponytail: O(n²) の走査。件数が数百を超えたら index を足す
# ponytail: 素朴なヒューリスティック。誤判定が実害になったら規則をデータにする
```

上限が見えない簡略化、または角を切っていない通常の実装には、このコメントを付けない。
