# 原因を直す

バグ報告は症状の名前である。症状が出た経路だけを塞がない。

## 流れを辿る

1. 報告されている入力、画面、ログから、実際に通る関数を特定する。
2. その関数が何を仮定し、どこで壊れるかを読む。
3. 同じ関数を呼んでいる箇所をすべて grep する。
4. 共有している仮定が誤りなら、共有関数を一度直す。

チケットが名指した呼び出し元だけにガードを足すと、隣の呼び出し元は同じバグのまま残る。

呼び出し元ごとの修正は、共有関数の修正より差分が大きく、漏れやすい。

## 直す場所

- 壊れている仮定が一つの関数にあるなら、その関数を直す。
- 壊れているのがデータの形なら、作る側か、信頼境界で一度検証する。使う側すべてには散らさない。
- 直した結果、他の呼び出し元の正しい動作を壊さないことを確認する。

## 最小差分との関係

原因を理解する前の最小パッチは、二つ目のバグである。

最短の差分が勝つのは、直すべき共有の地点が分かったあとである。
